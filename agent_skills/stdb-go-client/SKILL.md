# SpacetimeDB Go Client Authoring

Build Go programs that connect to a SpacetimeDB database over WebSocket using
`go.digitalxero.dev/spacetimedb-client`: subscribe to SQL queries, mirror rows in a
local cache, react to changes, and invoke server-side reducers and procedures.

**Import paths are always `go.digitalxero.dev/spacetimedb-client/...`** — never
`github.com/clockworklabs/...`. Requires Go 1.25+.

| Package | Import path | Purpose |
|---------|-------------|---------|
| client | `go.digitalxero.dev/spacetimedb-client/client` | `DbConnection`, subscriptions, reducers, one-off queries |
| cache | `go.digitalxero.dev/spacetimedb-client/client/cache` | Row cache, `TableDef`, typed caches, change callbacks |
| bsatn | `go.digitalxero.dev/spacetimedb-client/bsatn` | Binary serialization: `Writer`, `Reader`, `Serializable` |
| types | `go.digitalxero.dev/spacetimedb-client/types` | `Identity`, `ConnectionId`, `Timestamp`, `Uint128`, `Uuid`, `ScheduleAt`, ... |
| protocol | `go.digitalxero.dev/spacetimedb-client/client/protocol` | Only needed for `Compression` constants |

## Core lifecycle

Every client follows the same sequence — build, register tables, run, subscribe, call:

```go
conn, err := client.NewDbConnection().
    WithUri("ws://localhost:3000").
    WithDatabaseName("my_db").
    OnConnect(func(c client.DbConnection, id types.Identity, token string) {
        // Fires inside the event loop once the server sends identity+token.
        // Safe place to Subscribe and CallReducer.
    }).
    OnDisconnect(func(c client.DbConnection, err error) { /* ... */ }).
    Build(ctx) // dials the WebSocket; returns *ConnectionError on failure
if err != nil { log.Fatal(err) }

conn.RegisterTable(playerDef{})   // MUST happen before Run

if err := conn.Run(ctx); err != nil { /* connection lost or ctx cancelled */ }
```

Other builder methods: `WithToken(token)` (reconnect auth), `WithCompression(protocol.CompressionNone|Brotli|Gzip)`
(default None), `OnConnectError(func(error))`, `OnReducerError(func(error))`.

## The event loop: why you never need mutexes

`Run(ctx)` blocks and processes **every** WebSocket message and command in that one
goroutine. All cache mutations, subscription bookkeeping, and callbacks
(`OnConnect`, `OnApplied`, `OnInsert`, ...) execute sequentially inside `Run`, so there
is exactly one writer and no locks are needed — do not add your own. `CallReducer`,
`Subscribe(...).Build()`, `OneOffQuery`, and `Disconnect` are safe from any goroutine
because they just post commands to an internal channel that `Run` consumes.

Consequences you must respect:
- Call `Run` exactly once; when it returns the connection is done (no auto-reconnect —
  rebuild the connection to reconnect, passing `WithToken(conn.Token())`).
- Keep callbacks fast; a blocking callback stalls all message processing.
- Never call `CallProcedure` or `OneOffQuery` from inside a callback — they block
  waiting on the event loop that would be running the callback (deadlock).

## Tables and the row cache

Register a `cache.TableDef` per table (name must match the server exactly):

```go
type playerDef struct{}
func (playerDef) TableName() string { return "Player" }
func (playerDef) DecodeRow(r bsatn.Reader) (any, error) { /* read fields in order */ }
func (playerDef) EncodeRow(row any) []byte { /* write fields in order */ }
// Optional but strongly recommended — enables OnUpdate instead of delete+insert pairs:
func (playerDef) PrimaryKey(row any) any { return row.(*Player).ID }
```

React to changes and read state via the cache (all On* methods return a `CallbackID`
for `RemoveCallback`):

```go
tc := conn.Cache().GetTable("Player")
tc.OnInsert(func(row any) { ... })
tc.OnDelete(func(row any) { ... })
tc.OnUpdate(func(oldRow, newRow any) { ... }) // requires PrimaryKey
n := tc.Count()
tc.Iter(func(row any) bool { return true })   // return false to stop
```

## Subscriptions, reducers, procedures, one-off queries

```go
sub, _ := conn.Subscribe("SELECT * FROM Player", "SELECT * FROM Item").
    OnApplied(func() { /* initial rows are now in the cache */ }).
    OnError(func(err error) { /* *SubscriptionError */ }).
    Build()
sub.Unsubscribe() // later; each Build() is an independent subscription

conn.CallReducer("create_player", &createPlayerArgs{Name: "Alice"}) // fire-and-forget
raw, err := conn.CallProcedure(ctx, "get_stats", args)  // blocks for BSATN result
rows, err := conn.OneOffQuery("SELECT * FROM Player")   // raw BSATN rows, bypasses cache
```

Reducer args implement `bsatn.Serializable` (`WriteBsatn(w bsatn.Writer)`); pass `nil`
for no-arg reducers. Reducer failures arrive asynchronously via the builder's
`OnReducerError` as `*ReducerError` — `CallReducer`'s return value does not report them.
`OneOffQuery` returns `[][]byte`; decode each with your `TableDef.DecodeRow`.

## Generated bindings

Prefer generated bindings over hand-written defs when a server is available:

```bash
stdb-go generate client -d my-database   # writes package module_bindings/ by default
```

This emits `types_generated.go`, `bsatn_generated.go`, `tables_generated.go`,
`reducers_generated.go`, `procedures_generated.go`, `views_generated.go`, and
`module_generated.go`. Use the `ModuleBindings` aggregator — it registers every table
with type-safe caches (`cache.TypedTableCache[*T]`, no `any` assertions):

```go
bindings := module_bindings.NewModuleBindings(conn) // before conn.Run
bindings.Player.OnInsert(func(p *module_bindings.Player) { ... })
module_bindings.CallCreatePlayer(conn, "Alice", 100)
```

Never edit `*_generated.go` files; regenerate instead.

## Common mistakes

- Registering tables after `Run` has started — rows silently fail to cache.
- Adding mutexes around cache access "for safety" — the event loop already serializes.
- Expecting `CallReducer` to return server errors — wire up `OnReducerError`.
- Blocking inside callbacks, or calling `CallProcedure`/`OneOffQuery` from one.
- Encoding struct fields out of schema order — BSATN has no field names; order is the contract.
- Using `github.com/clockworklabs/...` import paths.
